Team challenge

    
    
      
  1. Start empty. Press Empty, set Wander, drag 1×, noise 1×. Press Reset stats and let it run 60 s. Write down the baseline and your hit rate (they should match).
    2. 
      
  2. Fix one problem at a time. Watch the event log and the range chart. Which misses are range noise? Which are the flywheel still spinning up? Which are shots at a goal that moved during a dropout? Add the one stage that targets that problem, run 60 s, record the hit rate and what changed.
    3. 
      
  3. Explain every stage. Open its code. In one sentence each, say what it reads, what it changes, and what it costs (held shots, lag).
    4. 
      
  4. Beat the reference. The mentor pipeline is hidden behind Reveal. Try to match or beat its hit rate before you look. Report your spec string, your hit rate, and your shots-per-minute.
    5. 
      
  5. Push it to the robot. Copy the Java, paste over ShooterConfig, build, run the Shooter Calibration OpMode once for a real table, then Shooter TeleOp.
    6. 
    

    
Writing a new stage: add an entry to the DEFS object in this page's script, and the twin class in ShooterStages.java with the same name and tunables. The spec string is the contract between them.

  


  
Model assumptions: 55° launch angle, 0.35 m exit height, 1.00 m goal height, opening ±0.18 m, exit speed 0.0025 m/s per flywheel rpm. The calibration table has six points from 1 m to 5 m, from drag-free physics. Air drag shortens real flights by 2.5 cm × (ideal range − 2 m)² at 1×, which the table does not know about. Limelight runs at 30 fps. Per-tag range noise σ = 1.5 cm + 1.2 cm·d² (times the noise slider), detection probability falls with distance, 1.5% outliers, random 0.4–1.0 s dropouts. Flywheel is first-order with 0.5% jitter and loses 10% speed on each shot. Placeholders, to be tuned against the real robot.
